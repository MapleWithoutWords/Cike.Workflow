## Problem Statement

工作流设计器画布周边有三个停靠面板：活动面板（左）、属性面板（右）、问题清单（底）。今天它们的开合状态"不粘"且"该藏不藏、该驻不驻"：

- 三个面板的开合每次刷新/重进设计器即重置，习惯折叠某个面板的用户每次都要重新折一遍；
- 问题清单在校验通过（问题数归零）时自动收起，想常驻盯着"校验通过"或持续观察问题变化做不到；
- 属性面板在未选中节点时以"未选中节点"空态白占约 288px 画布宽度；可若改成"取消选中就自动收起"，又没有手段让它在该常驻时常驻。

熟悉 IDE 的用户（如 Visual Studio 工具窗的 pin）期望有一个"固定"机制来掌控面板的常驻与否。

## Solution

给三个停靠面板统一增加 **pin（固定）** 能力，并抽取共享的 dock 状态层：

- **被 pin** = 常驻锁定：开合状态跨会话持久化，且免疫一切被动自动展开/自动收起；
- **未 pin** = 会话级状态 + 按**相关性规则**自动隐藏（每个面板自定义相关性规则）；
- **仲裁准则**：被动自动行为服从 pin；用户自身动作发起的揭示（如发布被拦截时的强制展开）优先于 pin。

用户由此获得可预期、可掌控的面板布局：想常驻就 pin，想省心就交给相关性自动隐藏。

## User Stories

1. 作为工作流设计者，我想 pin 住常用面板，让它的开合状态在刷新/重进后保持不变，免得每次重摆布局。
2. 作为工作流设计者，我想让 pin 状态跨会话、跨定义长期记住，不用每打开一个定义重新 pin。
3. 作为工作流设计者，我想取消 pin 后面板恢复"会话级 + 按相关性自动隐藏"的行为，把控制权交还给系统。
4. 作为工作流设计者，我想 pin 按钮有清晰的视觉区分（已 pin / 未 pin），一眼看出当前状态。
5. 作为工作流设计者，我想在面板展开时从面板头部切换 pin，不用另找入口。
6. 作为工作流设计者，我想在面板折叠成细条后也能从 rail 上切换 pin，因为"pin 折叠"也是我常用的状态。
7. 作为工作流设计者，我想在未 pin 时选中节点属性面板自动展开，选中即可编辑属性。
8. 作为工作流设计者，我想在未 pin 时取消选中节点属性面板自动收起成细条，把画布宽度还给我。
9. 作为工作流设计者，我想在未 pin 时切换选中节点（节点 A→节点 B）属性面板也自动展开，因为切换选中同样是相关性转变。
10. 作为工作流设计者，我想手动收起属性面板后、在选中保持不变期间它保持收起，自动行为不跟我的手动操作打架。
11. 作为工作流设计者，我想 pin 住属性面板后它的开合不再被选中变化驱动，常开常关由我决定。
12. 作为工作流设计者，我想在未 pin 时出新校验问题问题清单自动展开，第一时间注意到问题。
13. 作为工作流设计者，我想在未 pin 时校验通过问题清单自动收起，不占画布高度。
14. 作为工作流设计者，我想在未 pin 时问题数变化但仍非零（N→M）保持我手动折叠的状态，修错过程中不被打扰。
15. 作为工作流设计者，我想 pin 折叠的问题清单不因出新问题自动展开，但头部条的红字计数始终可见，信息不被藏。
16. 作为工作流设计者，我想 pin 展开的问题清单不因校验通过自动收起，可以常驻观察校验状态。
17. 作为工作流设计者，我想点发布被拦截时即使问题清单被 pin 折叠也强制展开并定位首条问题，因为这是我主动发起的动作在索要结果。
18. 作为工作流设计者，我想活动面板永远不自动隐藏（无相关性规则），因为工具箱始终相关。
19. 作为工作流设计者，我想 pin 住活动面板后它的开合跨会话记住，习惯折叠的人不用每次重折。
20. 作为工作流设计者，我想未 pin 面板的开合在每次会话开始时按相关性规则取初值（活动=展开、属性=折叠、问题清单=折叠），行为可预期。
21. 作为工作流设计者，我想 pin/开合不进 undo/redo、不是画布内容、不发后端，不污染工作流定义本身。
22. 作为工作流设计者，我想只读模式下 pin 状态不冲突（该模式只渲染属性面板，共享同一份持久化键）。
23. 作为工作流设计者，我想三个面板的 pin 按钮位置与交互一致，形成统一心智模型。
24. 作为工作流设计者，我想 pin 按钮带 tooltip 说明用途，新手能看懂。
25. 作为工作流设计者，我想未 pin 进设计器时属性面板以折叠细条出现（而非空态占宽），画布更宽敞。
26. 作为维护者，我想全部 dock 语义集中在一个共享状态层，三个面板不再各自实现一套开合逻辑。
27. 作为维护者，我想 dock 语义在 composable 级（node 环境）可测，不必引入 DOM 测试栈。
28. 作为维护者，我想术语（停靠面板/固定 Pin/自动隐藏 Auto-hide/相关性规则/仲裁准则）进术语表，后人读得懂设计。

## Implementation Decisions

- 新增共享 dock 状态层（composable，模块级单例），唯一承载三个面板的 pin 标志与开合状态；三个面板组件与设计器视图改为薄消费方（一行绑定）。
- 状态模型：每面板两个正交状态——pinned（布尔，持久化）与 open（布尔；被 pin 时持久化、未 pin 时会话级）。
- 相关性规则（未 pin 时的自动隐藏）：活动面板无；属性面板 = 有选中节点，选中节点身份的任何变化（含节点间切换、与未选中互切）触发自动展开/收起，手动开合在选中保持不变期间保持有效；问题清单 = 存在校验问题（0→N 自动展开、N→0 自动收起、N→M 保持手动状态）。自动行为只在转变时刻触发。
- 仲裁准则：被动自动行为服从 pin（pin 折叠不因 0→N 展开、pin 展开不因 N→0 收起）；用户自身动作发起的揭示优先于 pin（发布被拦截强制展开；点击问题行定位时面板必然已展开，天然满足）。
- 持久化：localStorage，全局粒度（不分定义/工作区/只读模式），每面板一个键；持久化内容 = pin 标志 + 被 pin 时的开合状态；未 pin 的开合不持久化，会话初值按相关性规则取（活动=展开、属性=折叠、问题清单=折叠）。
- 设计器视图内现有的问题清单组件局部自动展开 watch 上提到 dock 层；发布被拦截的强制展开改为调用 dock 层的主动揭示入口。
- 交互细节：pin 图标用项目图标库 lucide 的 Pin/PinOff；展开态置于各面板头部右侧、与现有折叠按钮并排，pin 生效时着前景色；侧面板折叠后 rail 上同样提供 pin 切换；问题清单的 pin 置于常驻头部条右侧；tooltip 文案"固定面板 / 取消固定"。
- 属性面板首次获得自动隐藏（取消选中自动收起）——这是一处可见的默认行为变化：未 pin 用户进设计器时属性面板以折叠细条出现。
- 术语与仲裁准则写入 CONTEXT.md 术语表（已完成）；"Web 化改写而非 VS 原义移植"的权衡落 ADR 0006。

## Testing Decisions

- 好测试的标准：只测外部行为——给定事件序列（选中身份变化、问题数转变、发布被拦截揭示、手动开合、pin 切换、模拟会话重启），断言各面板最终的展开/折叠与 pin 状态及持久化写入内容；不测实现细节（内部 ref 结构、watch 注册方式等）。
- 唯一缝：dock 状态层 composable 级测试（新测试文件），风格对齐 `useWorkflowDesigner.test.ts`：vitest node 环境、存储以 stub 注入、断言暴露的 ref。
- 覆盖点：三面板会话初值；属性面板全部转变（未选中→选中、选中→未选中、节点 A→节点 B、选中静止期间手动保持）；问题清单全部转变（0→N、N→0、N→M）；pin 免疫（pin 折叠不随 0→N 展开、pin 展开不随 N→0 收起、pin 属性面板不随选中变化）；主动揭示覆盖 pin（发布被拦截强制展开）；持久化往返（pin/被 pin 开合变化后写入、会话重启恢复、未 pin 开合不写入）；手动开合与 pin 切换。
- 不开第二条缝：三个面板与设计器视图为薄消费方，靠类型检查 + 手动走查覆盖；不引入 @vue/test-utils 与 DOM 环境。
- 先例：`src/composables/useWorkflowDesigner.test.ts`（composable 级、mock 生成 API client、断言暴露 ref）。

## Out of Scope

- VS 式失焦自动隐藏（折叠成边缘悬停临时页）——经评估明确否决。
- 多标签页状态同步（storage 事件）。
- 旧状态迁移（今天不存在任何面板持久化）。
- 键盘快捷键。
- 服务端用户偏好/跨设备同步。
- 按定义或按工作区记忆布局。
- pin/开合进入 undo/redo、画布内容或后端 payload。
- 组件级 UI 测试（面板与设计器视图的薄绑定）。

## Further Notes

- 术语表 CONTEXT.md 已收录：停靠面板（Dock Panel）、固定（Pin）、自动隐藏（Auto-hide）及三条相关性规则与仲裁准则。
- ADR 0006 记录核心权衡：pin 语义做 Web 化改写（常驻锁定 + 持久化 + 相关性自动隐藏的覆盖开关），而非移植 VS 的失焦悬停滑出；被否选项（VS 原义、仅持久化）与理由在案。
- 只读模式下仅属性面板渲染，与编辑模式共享同一组持久化键，无冲突。
- 实现时注意保留问题清单"手动折叠不被打扰"的既有产品意图（N→M 不自动展开），不得退化为无条件自动展开。
