## Problem Statement

工作流设计器的画布上，`For` / `ForEach` / `While` 这类**容器活动（Container Activity）**看起来和普通的一次性步骤节点（如 HTTP 请求、脚本）一模一样。用户看不出这些节点"里面有内容、可以**下钻（Drill）**进入其内部画布"，只能靠碰运气或读文档才知道要双击。下钻能力对用户是**隐形的**——不是功能缺失，而是缺少视觉可供性（affordance）。

## Solution

给每一个**可下钻节点**一个恒定、静默状态下即可见的"容器"视觉身份，让用户在一片节点里一眼就能认出"这是个有内部的东西，双击能进去"：

1. **层叠/景深母题**：把可下钻节点渲染成一副"牌堆"——主体背后垫一层错位的暗色圆角框，直观传达"我下面还压着一层画布"。这条线索走**景深/阴影通道**，与边框通道正交，因此和现有的 `isGeneric`（虚线框）、选中态（primary ring）、错误态（destructive ring）三套边框语义互不干扰、可同时成立。
2. **常驻 chevron（›）**：在节点最右边缘固定显示一个"进入"箭头，排在任何徽章（错误 / 运行状态 / generic 类型名）之后，作为"可进入"的恒定边缘符号，并配 tooltip「双击进入」教明动作。

chevron 仅作视觉可供性与提示，**不单独响应单击**；下钻的唯一触发方式仍是双击节点。该可供性在**可编辑画布、只读历史版本画布、工作流实例轨迹画布**上一律显示（下钻查看嵌套层在只读态同样合法且有价值，例如查看循环体内部的运行状态）。

## User Stories

1. 作为工作流设计者，我想在画布上一眼区分出哪些节点是容器（可下钻），以便我知道哪些节点里面还有子流程可以编辑。
2. 作为工作流设计者，我想让 `For` 节点在静默状态（未悬停、未选中）下就带有"可进入"的视觉线索，以便我不必逐个双击试探就能发现下钻能力。
3. 作为工作流设计者，我想让 `ForEach` 节点带有同样的容器视觉身份，以便循环类节点的可供性保持一致、可预期。
4. 作为工作流设计者，我想让 `While` 节点带有同样的容器视觉身份，以便所有循环容器的呈现统一。
5. 作为工作流设计者，我想让 `Flowchart`（纯容器）节点也显示容器身份，以便"能双击进去"这个承诺对所有可下钻节点一视同仁。
6. 作为工作流设计者，我想让后端定义的、前端无镜像但 wire JSON 带子活动的通用容器节点也显示容器身份，以便未知容器类型同样可被发现。
7. 作为工作流设计者，我想在鼠标悬停到 chevron 时看到「双击进入」的提示文案，以便明确知道触发下钻的具体动作。
8. 作为工作流设计者，我想在悬停可下钻节点时看到光标变化，以便获得"这里可交互"的即时反馈。
9. 作为工作流设计者，我想让容器视觉线索与选中态并存不冲突，以便选中一个容器节点时既能看出它被选中、又能看出它是容器。
10. 作为工作流设计者，我想让容器视觉线索与错误态并存不冲突，以便一个有校验问题的容器节点同时显示错误边框和容器身份。
11. 作为工作流设计者，我想让容器视觉线索与 `isGeneric` 虚线框并存不冲突，以便一个通用容器节点同时表达"未知类型"和"可下钻"两层信息。
12. 作为工作流设计者，我想让 chevron 排在错误 / 运行状态 / 类型名徽章之后、固定在最右边缘，以便右侧槽位有多个元素时也不互相遮挡。
13. 作为工作流设计者，我想让节点名称在容纳了图标、徽章、chevron 之后仍能正常截断，以便长名称不会把节点撑破或挤掉可供性符号。
14. 作为工作流设计者，我想让普通（不可下钻）步骤节点保持现有的干净外观，以便容器身份成为一种有意义的区分而非全量噪声。
15. 作为工作流查看者，我想在只读的历史版本画布上也看到容器身份与 chevron，以便我知道可以下钻进去查看嵌套层的内容。
16. 作为运维/排障人员，我想在工作流实例轨迹画布上看到容器身份，以便下钻进入循环体查看内部各活动的运行状态。
17. 作为工作流设计者，我想让"下钻深度"不影响层叠母题的强度（统一一层暗示即可），以便视觉语言保持简单、不因深层嵌套而变得杂乱。
18. 作为工作流设计者，我想让下钻的唯一触发方式仍是双击节点，以便交互模型单一、不会因为多出一条"单击 chevron 进入"的路径而误触或困惑。
19. 作为工作流设计者，我想在明暗两种主题下容器身份都清晰可辨，以便可供性不随主题退化。
20. 作为开发者，我想让这个可供性复用画布投影里已经算好的 `canDrill` 标志，以便不引入任何新的领域逻辑或模型改动。

## Implementation Decisions

- **复用既有标志，不新增领域逻辑**：可下钻与否由画布投影（`projection.ts`）中已经计算并已被单测覆盖的 `canDrill` 决定（For/ForEach/While/Flowchart 以及 wire JSON 带 `activities` 的通用容器均为 true）。本特性只是把这一既有标志**呈现**出来，不改任何领域模型、序列化、下钻算法或后端契约。
- **改动集中在节点渲染组件**：`DesignerNode.vue` 依据节点数据里的 `canDrill` 决定是否叠加容器母题与 chevron。
- **视觉通道正交**：容器线索走景深/阴影通道，避开已被 `isGeneric`（虚线）、选中（primary ring）、错误（destructive ring）占用的边框通道，确保四态可叠加共存。
- **裁切回退策略**：X6 vue-shape 节点为固定宽高，背后错位的层叠伪元素可能被节点边界裁切；若裁切，改用**边界内**的景深线索（底部 inset 双线 / 内阴影）达到同样"压着一层"的观感。此为纯实现细节，需在 dev server 上实测确认。
- **chevron 位置**：固定在最右边缘，排在 类型图标 → 名称 → 徽章（错误 / 状态 / generic 名）之后。
- **chevron 不可单击**：不单独绑定单击下钻，避免 X6 vue-shape 内 click 冒泡触发 node:click（选中）而需要额外阻断传播，也避免引入第二套交互模型。下钻唯一触发方式保持为双击节点主体。
- **hover 反馈**：hover chevron → `cursor: pointer` + tooltip「双击进入」；节点主体光标不变（不把整节点设为 zoom-in，以免与"可拖拽"语义打架）。
- **不按 interactive 关闭**：可供性在可编辑、只读、实例轨迹三种画布上一律渲染。
- **统一对待**：所有 `canDrill` 节点使用同一套容器身份，不区分容器种类，层叠层数不映射嵌套深度（统一一层暗示）。
- **不产文档**：不改 `CONTEXT.md`（这是 UI 可供性/实现细节，而领域概念「容器活动 / 下钻」术语表已收录）；不写 ADR（节点样式可随时回退，不满足 ADR"难以逆转"门槛）。

## Testing Decisions

- **好测试的标准**：只在既有的纯函数缝上断言外部行为，不测实现细节（不测具体 CSS/伪元素）。
- **不引入新缝**：判断"能否下钻"的 `canDrill` 早已在纯投影缝计算并被 `designer.test.ts` 的 `CanDrillInto_*` 用例覆盖（ForEach / 通用 Sequence 容器 / 标量 generic / 带自连的容器等）。本特性无新增逻辑缝；可供性是 vue-shape 组件内的表现层样式，在本项目测试基建下组件级样式/局部状态不可测。
- **回归守护**：确保既有 `canDrillInto` 相关单测保持全绿（本改动不应触碰投影逻辑）。
- **视觉验证（人工）**：在 5173 dev server 上走查并截图确认——(a) For/ForEach/While/Flowchart/通用容器节点静默态即可见容器母题与 chevron；(b) 普通节点外观不变；(c) 容器 + 选中 + 错误三态叠加时层次清晰不打架；(d) chevron 排在徽章之后、名称正常截断；(e) hover chevron 出现「双击进入」tooltip 与指针光标；(f) 明暗主题下均可辨；(g) 只读 / 实例画布上同样显示。
- **Prior art**：`src/core/designer/designer.test.ts` 中对 `canDrillInto` 的断言。

## Out of Scope

- 内联/嵌入式嵌套渲染（把子流程直接画在同一张画布的容器框内）——本特性只做"下钻模型"的视觉可供性。
- 让 chevron 可单击直接下钻（保持双击为唯一触发）。
- 改动双击下钻行为、下钻算法、面包屑导航或 NodeId 计算。
- 层叠层数随嵌套深度变化的视觉。
- 任何后端 / 活动描述符（ActivityDescriptor）/ 序列化契约改动。
- 为不可下钻的普通节点添加容器线索。

## Further Notes

- `canDrill` 标志已经端到端流通（投影 → 节点数据），本特性纯粹是"把已有信息画出来"，改动面小、风险低、可轻易回退。
- 右侧槽位当前对干净的 For/ForEach/While 节点是空的（非 generic 不显示类型名、无错误、无运行状态），chevron 落位无历史包袱；只有当容器节点同时带徽章时才需按"徽章在前、chevron 在末"的顺序排布。
