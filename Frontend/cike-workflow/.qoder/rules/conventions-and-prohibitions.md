# General Conventions & Prohibitions

## Conventions

- **Commit messages**: Conventional Commits (feat / fix / test / docs / refactor) + Chinese description, e.g. `feat:工作流定义保存/发布全链路`
- **Language**: Communicate with user, commit messages, `.claude/rules/` and project docs in Chinese; code identifiers and comments in English.
- **Change volume**: When non-mechanical changes exceed ~500 lines, propose a split plan before starting.
- **Layering discipline**: Business logic does not go into `Service.Open` — the host only does assembly and entry.
- **Auto-formatting**: After code changes, auto-format — backend runs `dotnet format <project>.csproj` on changed projects, frontend runs `pnpm lint:fix` once lint script is configured (not yet) — no approval needed; but only commit formatting results for files you changed, don't sweep unrelated files into the same commit.
- **Tests accompany changes**: When modifying core logic like workflow execution, serialization, repositories, must同步 add or update tests (follow `.claude/rules/testing.md`, core behavior优先 integration tests); for bug fixes, write reproduction test first then fix.
- **File size**: New features go in new files; when a single file exceeds ~800 lines, don't keep adding unless there's a clear reason.

## Prohibitions

- **No decompilation**: Do not use dnSpy / ILSpy / dotPeek / ildasm or similar tools to decompile DLLs or other binaries. When encountering unfamiliar framework/library behavior, handle in order: ① Read source code and official docs → ② Web search → ③ Ask user. Do NOT guess framework behavior from training memory.
- **No hand-modifying generated files**: EF Core migrations (`*ModelSnapshot.cs`, `*.Designer.cs`) can only be generated by `dotnet ef` commands; if hand-modification is truly needed, must get user approval first.
- **No unauthorized dependency introduction**: Must ask user before adding new NuGet packages or pnpm packages.
- **No breaking tests**: Do not modify assertions, delete, or skip tests to make them pass.
- **No scope expansion**: Only change files required by the task, do not refactor, rename, or clean up unrelated code.
- **No hiding problems**: Test failures, verification failures, unconfirmed behavior must be reported truthfully, do not gloss over or claim completion.
