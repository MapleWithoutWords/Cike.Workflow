# 页面：流程实例 Instances（列表 + 详情）

> 从属 `../MASTER.md`。核心任务：**定位一次执行为什么卡住 / 失败**，并把证据（变量、异常、子调用）看清。
> 实例域后端查询/控制能力尚未实现（MASTER §8）→ 本页**设计就绪、界面缺席**：不放假数据、不给假按钮（取消 / 挂起 / 子实例查询等待能力就绪再启用）。

## 列表结构
```
工具栏：[搜索名称/关联ID] [状态▾] [定义▾] [时间范围▾]    时效条(更新于·暂停·刷新)
生效筛选 chips（可单个移除，多则收纳为可点 +n）
表：☑ | 名称 | 定义·版本 | 状态徽标 | 故障数 | 开始 | 耗时 | 关联ID | 操作
分页 ｜ 勾选→批量条（控制类操作就绪前不出现）
```
- 行：名称空则显示 `#{id}`；定义列 `名称 @v{版本}` 可跳该定义 / 调试视图；`故障数>0`（`IncidentCount`）红色计数角标（色+数字，不单靠色）；耗时等宽（开始 = 创建时间，结束 = `FinishedAt`；无独立开始时间字段）；进行中显示「已运行 …」并随更新增长。
- 筛选：状态多选（六态）、定义（可搜选择器）、时间范围（原生日期输入 + 今天 / 24 小时 / 7 天快捷，**不引入日历控件**）。默认按开始时间倒序、列头显示排序方向。**筛选与排序结果可分享**（同一 URL 复现同一列表）。
- 空态：无实例 → 引导「去发布并运行一次」；筛选无果 → 清除筛选。

## 详情结构（三段式）
```
头部：状态徽标 + 名称 + id(等宽) ｜ 定义@版本 ｜ 关联ID(可复制) ｜ 起止/耗时 ｜ [在画布中查看执行]
标签：执行时间线 ｜ 变量 ｜ 子实例 ｜ 异常(N)
┌ 左：活动执行树（按调用嵌套关系还原）    ┌ 右：选中活动的证据
│  每行：图标+名称+状态徽标+耗时          │  基本信息 / 输入 / 产出 /
│  故障行红色；进行中行左侧细进度条        │  状态 / 属性 / 元数据 / 书签
│  点选一行 → 右面板切换                  │  （JSON 视图，见下）
│  深层级默认折叠、可展开                 │
└────────────────────────────────────────┴────────────────────────────┘
```
- **执行时间线**：每个活动的状态用 §3 色形文；`等待外部信号`（书签）用小图标 + tooltip 标注——这是「为什么没继续跑」的关键线索。
- **证据 JSON 视图**：等宽字体、可折叠 / 展开、按路径搜索、值一键复制、长字符串截断可看全；异常区 `destructive` 左描边 + 堆栈保留换行；大对象默认适度折叠。右面板分区**直接映射活动执行记录字段**：基本信息（`ActivityName`/`ActivityType`+版本/`Status`/`AggregateFaultCount`）、输入=`Payload`、产出=`Outputs`、状态=`ActivityState`、属性=`Properties`、元数据=`Metadata`、书签=`HasBookmarks`、异常=`Exception`。
- **变量页**：整体运行状态的 JSON 视图 + 路径定位（如 `input.orderId`）。
- **异常页**：异常记录列表，点一条 → 定位到时间线对应活动。异常体（`ExceptionState`）含 类型名 / 消息 / 堆栈 / **内层异常链**——须以缩进或「展开下一层」呈现整条 inner-exception 链，不只显示最外层。
- **子实例页**：能力就绪前不出现该标签（`ParentWorkflowInstanceId` 反查无端点）。

## 呈现纪律
- 活动状态六色映射与列表 / 时间线 / 画布**三处完全一致**（§3）。
- 耗时 / 时间戳：相对 + 绝对双显（悬停出绝对值），统一标注时区。
- 进行中的详情持续更新到进入终态为止；更新**不打断**用户当前的展开 / 选择；进入终态给一次轻提示。
