# 工作流输入与输出的默认表达式由运行时补值

`InputDefinition` 与 `OutputDefinition` 都继承 `ArgumentDefinition` 并持有 `DefaultValue: Expression`，但现有运行时没有落实对应的缺省值语义。我们决定：只有名称键不存在时才求值默认表达式；显式 `null` 是有效值，不触发默认值。输入默认值在工作流开始执行前补齐，输出默认值仅在工作流正常完成且该输出从未写入时补齐；取消或故障终态不补默认输出。默认表达式求值或目标类型转换失败时，沿用表达式执行错误语义使工作流故障，不静默吞错。

输入默认表达式只允许 Literal、Liquid、JavaScript，不允许使用 Input 或 Variable 名称引用类型。输出默认表达式允许 Literal、Liquid、JavaScript、Input、Variable 五类，可读取工作流最终输入与变量；显式产生的输出始终优先于默认表达式。目标类型由 `Type + IsArray` 通过现有序列化类型注册表解析，前端类型选择使用后端已有的类型列表接口。

## Considered Options

- 把显式 `null` 当作缺失值：被否。调用方或流程无法再明确表达空值。
- 在取消、故障时也补齐输出：被否。这会让失败执行看起来满足了正常返回契约，并可能掩盖真实执行状态。
- 前后端在同一交付中实现：本次未采用。当前交付只负责前端配置能力，运行时补值由后端独立任务承接。

## Consequences

- 后端后续需在启动阶段补齐缺失输入，并在进入正常完成终态前补齐缺失输出；两条路径均复用现有表达式求值器和类型注册表，不属于本次前端交付范围。
- 后端画布校验需校验输入默认表达式的类型白名单，以及输入、输出、变量、结果各自集合内的名称必填与唯一性。
- 前端输入默认值编辑器只展示三种允许类型，输出默认值编辑器展示全部已注册类型。
