# 停靠面板 pin 做 Web 化改写：常驻锁定 + 持久化 + 相关性自动隐藏的覆盖开关，不移植 VS 失焦悬停滑出

> 右侧属性面板的内容切换与取消选中行为已由 ADR 0008 修订；本 ADR 的 pin、持久化和仲裁规则继续有效。

设计器三个停靠面板（活动/属性/问题清单）需要"常驻 vs 自动隐藏"的掌控机制，业内参照物是 Visual Studio 工具窗的 pin（未 pin = 失焦后折叠成边缘悬停临时页）。我们决定做 Web 化改写：**pin = 常驻锁定**（开合状态以 localStorage 全局粒度跨会话持久化，且免疫一切被动自动展开/收起）；**未 pin = 会话级状态 + 按各面板相关性规则自动隐藏**（活动面板无；属性面板 = 选中节点身份的任何变化；问题清单 = 存在校验问题，0→N 展开 / N→0 收起 / N→M 保持手动）。**仲裁准则**：被动自动行为服从 pin；用户自身动作发起的揭示（发布被拦截强制展开）优先于 pin。

## Considered Options

- 忠实移植 VS（失焦自动隐藏成边缘悬停临时页）：被否。Web 画布没有 IDE 工具窗焦点机制，悬停临时弹出会干扰节点拖拽与连线；在仅三个停靠面板的场景下成本远大于收益。
- pin 仅等于持久化（自动行为不变）：被否。只解决"状态不粘"，解决不了"问题清单变干净即自动收起、想常驻做不到"与"属性面板空态占宽却无手段常驻"两个痛点。
- 按定义或按工作区记忆布局：被否。布局偏好是人的习惯而非数据的属性，按定义分键会制造"这个定义里面板怎么是开的"的困惑。

## Consequences

- 属性面板首次获得自动隐藏（取消选中自动收起）；未 pin 用户进设计器时属性面板以折叠细条出现——一处可见的默认行为变化。
- pin 折叠的问题清单不因出新问题自动展开，信息可见性靠常驻头部条的红字计数兜底；发布被拦截的强制展开是唯一覆盖 pin 的揭示入口。
- dock 语义由单一模块级单例 composable 承载，三个面板与设计器视图为薄消费方；测试只开一条 composable 级缝（spec 见 GitHub issue #16）。
